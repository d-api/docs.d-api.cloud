## `messages.sent` event

<Warning>
  `messages.sent` fires **only** for messages sent through the D-API
  **API** (`/messages/send/*` and `/interactive/send/*`). Messages
  sent from the **phone itself** or from **other devices linked** to the
  same number do **not** trigger `messages.sent` — they arrive in
  [`messages.received`](/en/whatsapp/webhooks/messages-received) with `fromMe: true`.
</Warning>

Use this event to confirm that a message fired through the API was sent
successfully and to record the final content delivered to WhatsApp.

<Note>
  The payload has **exactly the same structure** as the `messages.received` event
  for the same `type` (same fields, `media_data` with `file_length`/`mimetype`,
  `context_info`, etc.), just with `fromMe: true`. For the full reference of
  all fields, see the
  [messages.received](/en/whatsapp/webhooks/messages-received) page.
</Note>

The difference is in the roles: `from` is **your** number (the session) and `to` is the
recipient.

<Note>
  When media is sent by **external URL**, the payload may include
  `pending_media_url` (the original URL provided in the request) inside
  `media_data`. Also, the message `id` (generated by whatsmeow) may come
  in **uppercase**.
</Note>

## Other sendable types

The types below can also be sent through the API. The exact `messages.sent`
payload format for these types is **not documented here** to avoid
incorrect examples — when sent, the webhook follows the same structure
as the corresponding [`messages.received`](/en/whatsapp/webhooks/messages-received),
with `fromMe: true`.

| Type | Endpoint |
|------|----------|
| poll | `POST /messages/send/poll` |
| album | `POST /messages/send/album` |
| nativeflow | `POST /interactive/send/nativeflow` |

<Note>
  Polls (`poll`) are reported in `messages.received` as `poll_update`
  (votes). An **album** sends multiple media items and may trigger more than one
  individual media event (`image`/`video`). Confirm the format in a test environment
  before handling these types in production.
</Note>

---

## Sending endpoints

Each sendable type maps to an API endpoint:

| Type | Endpoint |
|------|----------|
| text | `POST /messages/send/text` |
| image | `POST /messages/send/image` |
| video | `POST /messages/send/video` |
| audio | `POST /messages/send/audio` |
| document | `POST /messages/send/document` |
| sticker | `POST /messages/send/sticker` |
| location | `POST /messages/send/location` |
| contact | `POST /messages/send/contact` |
| poll | `POST /messages/send/poll` |
| reaction | `POST /messages/send/reaction` |
| album | `POST /messages/send/album` |
| list | `POST /interactive/send/list` |
| carousel | `POST /interactive/send/carousel` |
| nativeflow | `POST /interactive/send/nativeflow` |

<Warning>
  Avoid using `messages.sent` to trigger auto-reply automations.
  Since it confirms messages that **you yourself** sent through the API, treating it as
  a reply trigger can cause loops.
</Warning>
